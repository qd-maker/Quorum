# Quorum · RAG 错误模式（占位 / 未启用）

> **现状**：Quorum 当前 **未使用 RAG / 向量库 / 私有知识检索**。
> 它的"知识"全部来自实时联网搜索（Tavily / DuckDuckGo）+ 模型自身权重。
> 本文用作"将来若引入 RAG 应避开的坑"，避免破坏现有 UX。

---

## 0. 当前替代方案：联网搜索（不是 RAG）

| 维度 | Quorum 现状 | 真正的 RAG |
|---|---|---|
| 知识源 | Tavily Web 实时搜索（`backend/services/search_service.py`）| 私有文档向量化后存向量库 |
| 检索方式 | HTTP 全文搜索 → 取 top 5 → 文本 `format_search_context` 拼到 system prompt | embedding 余弦相似度 → top-k → rerank |
| 失败 fallback | DuckDuckGo HTML 解析 | 无（命中率不够就直接答错） |
| 时效性 | 当下最新（搜索）| 取决于最近一次入库时间 |

**结论**：在"基于公网信息回答最近事件"这类需求上，**实时搜索往往打败 RAG**。先评估"是否真的需要私有数据"，否则上 RAG 就是过度设计。

---

## 1. 引入 RAG 之前的灵魂三问

1. **是不是真的有"私有 / 不公开"的数据？** 没有就不上 RAG，用搜索。
2. **数据规模会超过 200K tokens 吗？** 不会就直接塞 system prompt（"长上下文 RAG"），不要先上向量库。
3. **回答正确率有可量化的验收标准吗？** 没有就先做 5 条 golden case 再写代码，否则后期没法调。

---

## 2. 假设未来要给 Quorum 加 RAG（例如"基于用户上传文档讨论"）

### 必须先做的设计

- **每个用户的向量库要按 `user_id` 隔离**（参考 `services/user_config.py` 的 per-user 模式），不能全局共享
- **检索阶段**应在 R1 之前完成，把检索结果注入 `_round1_system` 的 `search_block` 同一位置（`backend/services/orchestrator.py:73`），不要在 R1 里再发起检索（4 个模型 × 检索 = 4 倍调用）
- **共识阶段**不要再次检索，直接用 R1 已注入的上下文 + 各模型 summary

### 提前规避的坑

#### 坑 1：全局 chunk_size 一刀切
- **现象**：技术文档（代码块多）和散文（自然段长）用同一个 `chunk_size=500` → 代码块被切断、散文上下文丢失
- **修复**：按文档类型区分；代码 / 表格优先**按结构**切（函数 / 行）而非按字符数

#### 坑 2：embedding 用免费的 sentence-transformers，结果再调用 GPT-4o
- **现象**：embedding 是 384 维 cnSBERT，召回的 chunk 和问题语义弱相关 → GPT-4o 拿到一堆噪音 → 回答漂移
- **修复**：要么 embedding 也用 OpenAI `text-embedding-3-small`（$0.02/百万 token，几乎免费），要么本地用更强的 BGE-M3

#### 坑 3：未做 rerank
- **现象**：top-5 召回的"相似度第 1"经常不是"最能回答问题的那条"
- **修复**：top-20 召回 → cross-encoder rerank → top-3 喂模型；否则 RAG 回答质量上限被卡死

#### 坑 4：把检索失败当成"无结果"静默处理
- **现象**：向量库连接失败 → 召回 0 条 → 模型基于自身知识答 → 用户以为是基于自己的文档答的
- **修复**：检索失败必须 **明确告诉用户**"未能从你的文档中找到相关内容，以下是模型基于公开知识的回答"。Quorum 现有的 SSE event type 可以扩展加一个 `rag_status` 事件。

#### 坑 5：多文档 / 多产品混淆
- **现象**：用户传了 A 产品和 B 产品两份文档，问"A 的价格"，召回回了 B 的价格段落
- **修复**：检索时强制按 metadata 过滤（`document_id` / `product` 字段），不要只靠语义相似度

#### 坑 6：把"对话历史"也塞进向量库
- **现象**：每轮对话向量化后存库 → 用户一周后再来 → 召回到一年前的随口闲聊
- **修复**：对话历史走另外的存储（Redis 或 SQLite），**不要混入文档向量库**
